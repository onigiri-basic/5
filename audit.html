CRITICAL 🧩 XSS (Cross‑Site Scripting) риск: критический | решено ✅
📘 Что такое XSS? — тип атаки, при котором злоумышленник внедряет вредоносный JavaScript-код в веб-страницу. Скрипт выполняется в браузере жертвы, что позволяет красть cookies, сессии, подменять содержимое или перенаправлять на фишинговые ресурсы.

❌ Уязвимый сценарий (было): прямой вывод пользовательских данных без фильтрации.

⚡ потенциальная атака: ?search=<script>alert('session')</script>
<input value="<?php echo $_GET['search']; ?>">
<div><?php echo $userData['name']; ?></div>

✅ Исправленная логика: тотальное экранирование спецсимволов.

🔒 htmlspecialchars на каждый выход
<input value="<?php echo htmlspecialchars($_GET['search'] ?? '', ENT_QUOTES, 'UTF-8'); ?>">
<div><?= safeOutput($userData['name']) ?></div>
  • Все поля в index.php, edit.php, admin/*.php обёрнуты в htmlspecialchars
  • Собственная функция safeOutput() гарантирует кодирование.
MEDIUM 📄 Information Disclosure (утечка служебных данных) риск: средний | решено ✅
📘 Суть уязвимости: неконтролируемое отображение технических деталей — путей к файлам, дампов SQL-ошибок, версий PHP или структуры каталогов. Облегчает подготовку целенаправленных атак.
❌ Прямой вывод ошибок БД и включённый листинг папок:
error_reporting(E_ALL); ini_set('display_errors',1);
die("MySQL error: " . $e->getMessage());
# отсутствие Options -Indexes
✅ Логирование без отображения деталей + защита директорий
error_reporting(0); ini_set('display_errors',0);
error_log($e->getMessage());
echo "Ошибка обработки запроса";
# .htaccess: Options -Indexes
  • Настроена единая страница ошибок, без стека вызовов.
  • Запрещён индекс каталогов (Options -Indexes) во всех административных разделах.
CRITICAL 🗄️ SQL Injection (внедрение SQL-кода) риск: критический | решено ✅
📘 SQL-инъекция: атака через модификацию SQL-запроса посредством невалидированных данных. Позволяет злоумышленнику читать, изменять или удалять записи в БД, а в некоторых случаях — выполнить команды на сервере.
❌ Конкатенация строк в запросе (уязвимость на любом параметре)
$id = $_GET['id'];
$sql = "SELECT * FROM users WHERE id = $id";
mysqli_query($conn, $sql);
✅ Подготовленные выражения PDO (изоляция параметров)
$stmt = $pdo->prepare("SELECT * FROM applications WHERE id = :id");
$stmt->execute([':id' => $id]);
$data = $stmt->fetch();
  • Все запросы (входная форма, админ-панель, экспорт, статистика) переведены на PDO с параметрами.
  • Полное исключение прямого внедрения переменных в текст SQL.
HIGH 🎭 CSRF (Cross‑Site Request Forgery) риск: высокий | решено ✅
📘 CSRF (межсайтовая подделка запроса): атака, заставляющая браузер аутентифицированного пользователя отправить подложный HTTP-запрос на уязвимый сайт (смена пароля, удаление анкеты, создание пользователя) без его ведома.
❌ Отсутствие токенов в формах удаления / редактирования
<form method="POST" action="delete.php">
<input type="hidden" name="id" value="10">
</form>
✅ Генерация уникального CSRF-токена + валидация
$_SESSION['csrf_token'] = bin2hex(random_bytes(32));
<input type="hidden" name="csrf" value="<?= $_SESSION['csrf_token'] ?>">
// Проверка: hash_equals($_SESSION['csrf_token'], $_POST['csrf'])
  • Все формы, изменяющие состояние (создание, обновление, удаление), защищены CSRF-токенами.
  • Куки сессии с флагом SameSite=Strict и HttpOnly.
HIGH 📂 LFI / RFI (включение удалённых/локальных файлов) риск: высокий | решено ✅
📘 File Inclusion (LFI/RFI): уязвимость, возникающая при динамическом подключении файлов через параметры. LFI позволяет прочитать системные файлы (passwd, logs), RFI — выполнить удалённый скрипт, что ведёт к полной компрометации сервера.
❌ Include на основе GET-параметра
$page = $_GET['page'];
include($page . ".php");   // злоумышленник: ?page=../../etc/passwd
✅ Белый список разрешённых страниц
$allowed = ['dashboard','view','edit','stats'];
if (!in_array($_GET['page'] ?? 'dashboard', $allowed)) { die('Forbidden'); }
  • В проекте все инклюды статичны: include 'header.php'; — нет динамических путей из пользовательского ввода.
  • В php.ini отключены allow_url_include и allow_url_fopen.
HIGH 📎 Upload (загрузка вредоносных файлов) риск: высокий | ✅ не актуален / шаблоны защиты
📘 Небезопасная загрузка файлов: если веб-приложение позволяет загружать произвольные файлы без тщательной валидации, злоумышленник может отправить PHP-шелл или .htaccess с вредоносными инструкциями, что часто даёт полный контроль над хостингом.

🔹 В текущем приложении функционал загрузки отсутствует, поэтому вектор атаки не применим. Однако для будущих версий подготовлен защитный код.

🛡️ Комплексная защита при добавлении загрузчика:
✓ Проверка MIME-типа через finfo
✓ Белый список расширений (jpg,png,pdf)
✓ Генерация уникального имени (bin2hex(random_bytes(16)))
✓ Лимит размера 2 МБ
✓ Запрет выполнения PHP в папке uploads через .htaccess
  • .htaccess внутри директории загрузок содержит FilesMatch "\.php$" → Require all denied
